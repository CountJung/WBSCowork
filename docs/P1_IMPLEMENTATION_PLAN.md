# P1 팀 운영 기능 구현 계획

기준: `c366126` · 사용자 요청 2026-10-09. 이번 P1 범위는 PRD-040~043이다. QLT/OPS/RPT에는 명시 P1이 없으므로 기존 상태를 유지한다.

1. PRD-040: WBS와 별개인 같은 프로젝트 선행 업무. 프로젝트 단위 graph CAS, 순환 거부, 미완료 선행 업무가 있으면 시작/검토 요청/완료 거부. 재오픈은 기존 승인 이력을 덮어쓰지 않고 현재 차단을 별도로 표시한다. 현황 숫자에서 해당 카드 목록으로 이동한다.
2. PRD-041: 소스에 정의한 수동 예시 템플릿을 미리보고 제목/설명/산출물/기준/담당/날짜/포함 여부를 조정한다. 최대 20개를 원자적으로 생성하고 동일 token/payload는 한 번만 반영한다. 사용자의 파일/비공개 본문/권한을 복제하지 않는다.
3. PRD-042: 저장된 업무·제출 본문/파일명/작성자 검색. 최신/승인/모든 버전 규칙을 표시하며 현재 역할과 현재+당시 visibility를 count/list/snippet 전에 SQL로 적용한다.
4. PRD-043: 배정·검토·보완·승인·댓글의 수신자별 인앱 목록. 기존 원본 event를 사용하고 읽음 기록만 별도 저장한다. 재배정/권한 변경 후 현재 SQL 가시성을 다시 검사한다. 외부 발송·새 OAuth·정기 digest 없음.

기존 Google 인증, 전역 project/task 조회 정책과 private author/admin/SU 경계를 유지한다. D1과 native schema는 additive migration만 추가하고 기존 migration checksum을 수정하지 않는다. 계정/권한 변경·비밀정보·운영 데이터 영구 삭제는 범위 밖이다. QLT-015 차단된 cleanup 경합 검사는 재시도하지 않는다.

각 단계는 focused tests, lint/types/FSD, Worker build/회귀, 독립 정적 검토와 commit/push로 닫는다. Native migration SQL은 정확한 commit으로 별도 격리 검증하며 게시 전에 additive 적용 순서와 rollback 한계를 기록한다. 실환경은 기존 세션의 read-only QA를 우선하고 새 영구삭제 대상은 만들지 않는다.

## PRD-040 세부 계약

선행 미충족 상태에서는 시작·완료·검토 요청과 판정을 보류하고 기존 검토 취소/재오픈은 허용한다. 선행 업무가 다시 열려도 후행의 완료/승인 이력을 자동 취소하지 않고 별도 경고를 표시한다. 선행 연결된 개별 업무는 관계를 먼저 해제해야 삭제할 수 있다. 프로젝트 전체 파기는 기존 명시 확인 계약을 유지한다. 삭제 경합 경로는 이번에 실제 영구 삭제로 재현하지 않으며 정적 검토 범위를 기록한다.
