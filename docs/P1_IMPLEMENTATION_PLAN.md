# P1 팀 운영 기능 구현 계획

기준: `c366126` · 사용자 요청 2026-10-09. 이번 P1 범위는 PRD-040~043이다. QLT/OPS/RPT에는 명시 P1이 없으므로 기존 상태를 유지한다.

1. PRD-040: WBS와 별개인 같은 프로젝트 선행 업무. 프로젝트 단위 graph CAS, 순환 거부, 미완료 선행 업무가 있으면 시작/검토 요청/완료 거부. 재오픈은 기존 승인 이력을 덮어쓰지 않고 현재 차단을 별도로 표시한다. 현황 숫자에서 해당 카드 목록으로 이동한다.
2. PRD-041: 소스에 정의한 수동 예시 템플릿을 미리보고 제목/설명/산출물/기준/담당/날짜/포함 여부를 조정한다. 최대 20개를 원자적으로 생성하고 동일 token/payload는 한 번만 반영한다. 사용자의 파일/비공개 본문/권한을 복제하지 않는다.
3. PRD-042: 저장된 업무·제출 본문/파일명/작성자 검색. 최신/승인/모든 버전 규칙을 표시하며 현재 역할과 현재+당시 visibility를 count/list/snippet 전에 SQL로 적용한다.
4. PRD-043: 배정·검토·보완·승인·댓글의 수신자별 인앱 목록. 기존 원본 event를 사용하고 읽음 기록만 별도 저장한다. 재배정/권한 변경 후 현재 SQL 가시성을 다시 검사한다. 외부 발송·새 OAuth·정기 digest 없음.

기존 Google 인증, 전역 project/task 조회 정책과 private author/admin/SU 경계를 유지한다. D1과 native schema는 additive migration만 추가하고 기존 migration checksum을 수정하지 않는다. 계정/권한 변경·비밀정보·운영 데이터 영구 삭제는 범위 밖이다. QLT-015 차단된 cleanup 경합 검사는 재시도하지 않는다.

각 단계는 focused tests, lint/types/FSD, Worker build/회귀, 독립 정적 검토와 commit/push로 닫는다. Native migration SQL은 정확한 commit으로 별도 격리 검증하며 게시 전에 additive 적용 순서와 rollback 한계를 기록한다. 실환경은 기존 세션의 read-only QA를 우선하고 새 영구삭제 대상은 만들지 않는다.

## PRD-040 세부 계약

선행 미충족 상태에서는 시작·완료·검토 요청과 판정을 보류하고 기존 검토 취소/재오픈은 허용한다. 선행 업무가 다시 열려도 후행의 완료/승인 이력을 자동 취소하지 않고 별도 경고를 표시한다. 선행 연결된 개별 업무는 관계를 먼저 해제해야 삭제할 수 있다. 프로젝트 전체 파기는 기존 명시 확인 계약을 유지한다. 삭제 경합 경로는 이번에 실제 영구 삭제로 재현하지 않으며 정적 검토 범위를 기록한다.

## PRD-041 생성 계약

예시 템플릿은 버전이 있는 소스 데이터이며 생성 뒤 catalog 변경과 무관하다. 미리보기의 모든 업무는 기본 미배정이고, 상위 제외 시 하위도 제외한다. 변경 가능한 이름/설명/산출물/기준/날짜/담당만 plain task로 복사하고 접근권한/파일/검토 이력은 복사하지 않는다. UI는 저장 중 미리보기 수정·취소를 막고, 검증 실패 시 입력한 미리보기를 유지한다. 동일 token/payload는 원래 생성 결과를 반환하고 다른 내용의 재사용은 거부한다. 원자적 생성 receipt는 업무가 별도로 삭제되더라도 재실행하여 부활시키지 않는다.

## PRD-042 검색 규칙

최신본이 기본이고 현재 승인본은 취소/무효화되지 않은 선택된 현재 버전만 뜻한다. 이전 버전은 현재 제출물과 당시 snapshot의 공개 범위를 동시에 만족해야 한다. 버전 필터는 제출물에만 적용하며 업무 카드는 기존 인증 사용자 공유 정책을 유지한다. LIKE의 %, _, !는 literal로 검색한다. OCR/원격 수집/벡터 검색은 사용하지 않는다.

## PRD-043 알림 계약

알림 본문을 따로 복제하지 않고 기존 배정/검토/댓글 event에서 현재 수신자·역할·상태·가시성을 매번 조회한다. A→B→A 재배정은 과거 배정 알림을 부활시키지 않는다. 검토 취소/새 요청/새 버전/권한 변경으로 더 이상 유효하지 않은 행은 count/list/읽음 저장 모두에서 제외한다. 원래 제출 작성자의 소유 조회권은 기존 정책대로 유지하므로 담당에서 빠지더라도 자신의 제출물 댓글 알림은 볼 수 있다. 읽음 receipt는 사용자/project/source ID와 시각만 저장하며 업무·검토 이력을 삭제하지 않는다. 전체/미확인과 페이지를 보존해 읽음 처리한다.

## 게시 순서와 복구 한계

D1 0010(선행 관계와 project CAS 2열) → 0011(template receipt) → 0012(notification read receipt)를 기존 0000–0009 뒤에 추가한다. Native는 immutable v1–v5 뒤 v6–v8이다. 기존 table/role/파일/history의 변환·삭제, 운영 계정 변경, 외부 서비스 전송은 없다. 게시 전 현재 기존 표의 row와 운영 계정/기존 purge receipt를 읽기 기준으로 보관하고 게시 후 비교한다. 새 기능의 정상 쓰기 전에는 새 표가 비어 있는 것이 기대 상태다.

문제가 있으면 같은 schema를 남긴 채 호환되는 코드로 되돌리는 것을 우선한다. 옛 앱은 새 의존성 제약/알림 기능을 알지 못하므로 새 기능 사용 후 단순 코드 rollback은 업무 규칙을 완전히 유지하지 못한다. 자동 down migration이나 새 표 영구 삭제로 복구하지 않는다. 실제 데이터 조정이 필요하면 별도 대상을 확인한다.
