## 변경

- theme에서 Container 기본 xl을 중앙 관리하고 업무/관리자/버그 목록 등의 개별 lg 지정을 제거했다. 개인정보와 버그 상세의 명시적 md는 긴 글을 읽는 용도로 유지한다.
- 헤더 grid: xl(1536px) 이상 한 행, md(900px)~xl 미만 메뉴를 둘째 행에 배치한다. md 미만은 기존 Drawer를 유지한다. 메뉴를 overflow로 숨기지 않는다.
- 메뉴/로그인·로그아웃 버튼은 nowrap/non-shrinking, 브랜드는 한 줄, 본문은 `keep-all`로 한국어 단어를 유지하고 아주 긴 문자열만 `anywhere`로 줄바꿈한다. 이름 칩은 제한된 폭의 ellipsis와 전체 title을 제공한다. 숨겨진 모바일 아이콘 때문에 브랜드에 남던 margin도 gap으로 해결한다.
- 반경 단위 4px로 복구해 일반 카드 16px, 일부 카드 12px가 되며 버튼/칩의 명시적 pill 모양은 유지한다. 작업 상단 통계 칩은 줄바꿈 가능한 그룹으로 배치한다.

## 회귀 하네스

`npm run build:sites && npm run test:ui:layout`.

- Python Playwright + `/usr/bin/chromium` 기본(`CHROMIUM_PATH`로 실행 파일 선택 가능). Chromium sandbox는 항상 켠다. 이 실행기는 관리형 shell sandbox 안에서 SUID sandbox 구성 오류가 있었으므로 승인된 sandbox 외부 실행으로 검증한다. Chromium 보안 옵션·운영 설정은 바꾸지 않는다.
- Miniflare의 메모리 D1/R2에 migration을 적용하고 합성 계정/프로젝트/업무만 생성한다. 외부 URL은 차단한다. loopback gateway는 GET/HEAD만 HTTPS fixture origin에 전달하며 브라우저의 합성 쿠키 이름을 표준 HTTPS 이름으로 대응시킨다. production JS/CSS/font 파일은 그대로 로컬 제공한다. 실제 OAuth나 게시 Site로 요청하지 않는다.
- 서버 HTML만 보는 검사가 아니다. 실제 session fetch·hydration 후 관리자 메뉴와 모바일 Drawer를 열어 항목을 확인한다. 수평 넘침, 헤더/본문 폭, 버튼 한 줄과 컨테이너 경계, 브랜드 잘림, 패널 반경, 긴 이름 title을 검사한다.
- 빈 작업·업무 있는 작업·관리 개요·내 버그 제보·관리자 버그 리뷰 및 긴 이름. 1920/1699/1440/1280/1024/390px. 1699/1024/390에서는 guest/member/admin/비로그인 홈도 확인한다. 별도 1699 dark 샘플을 남긴다.
- `.test-artifacts/layout/after/`: PNG와 `results.json`. `--before`는 기준 worktree에서 1699/1280/390의 빈 작업·긴 이름 6조건을 실행하며 예상 실패로 exit1이다. 결과에는 세션 token을 저장하지 않는다.

## 적용 절차

이 브랜치 push는 NAS와 공개 Site를 반영하지 않는다. 운영 main 강제 병합·Site 재게시·운영 DB/schema/권한 변경은 하지 않는다. 운영 반영 후 실제 로그인/기존 자료/브라우저의 수동 인수는 별도다.

- NAS: 검토한 fix 커밋을 main에 정상 통합한 뒤 [main NAS_UPDATE_GUIDE.md](https://github.com/CountJung/WBSCowork/blob/main/docs/NAS_UPDATE_GUIDE.md)의 보존/빌드/기동·수동 인수 절차를 운영자가 수행한다.
- Sites: 같은 fix 커밋을 `feat/sites-deployment`에 cherry-pick하고 기본 `build=vinext build`를 유지한다. `build:sites`, `test:ui:layout`, Worker auth 등을 확인한 뒤 별도 공식 Sites 게시 절차를 수행한다. main의 native 기본 build 통합 커밋은 클라우드에 강제로 병합하지 않는다.
- 이번 수정에는 migration·새 환경 변수·역할 변경이 없다. 정확한 push SHA/원격 일치와 CI 조회 결과는 최종 인계에 기록한다. 저장소에는 `.github/workflows`가 없다. `gh api`는 Forbidden이었으나 연결된 GitHub 읽기 경로에서 저장소 권한과 Actions run 전체0건을 확인했다. push 뒤 정확한 SHA의 checks/runs를 다시 확인하며 로컬 검사 통과를 CI 성공으로 바꾸어 표현하지 않는다.


클라우드 적용용 `fix/shared-desktop-layout-sites`는 공통 수정 `3f624501d942db22ab0cb3df699de036b3b2a43c`를 Sites 기준에 적용한 브랜치다. 소스/테스트는 동일하며 COMPLETED_LOG/HARNESS_MAP의 NAS 전용 이력 충돌만 클라우드 문맥으로 해결했다. 기존 기본 `build=vinext build`를 유지하고 운영 feat/sites-deployment에는 push하지 않는다.

후속 사용자 승인으로 `feat/sites-deployment`를 정상 fast-forward하고 `0a2cbb5`를 version11에 게시했다. 위 미게시 설명은 최초 소스 수정 인계 단계의 범위다. 현재 결과와 네트워크 제한은 [게시 기록](SITES_LAYOUT_PUBLICATION_2026-10-19.md)을 따른다. NAS main과 NAS 서비스는 변경하지 않았다.
